# ملاحظات على حزمة الفريق (`team_data/`) والربط مع المطابِق

الحزمة مفكوكة من `sawn-mock-data.zip` كما هي: سبعة ملفات، وتطابق بصمة SHA-256 لكل ملف أصله في الـZIP. لم يُعدَّل أي ملف فيها. كل البيانات وهمية: أرقام `96650000xxxx`، ورمز بنك `00`، ونطاقات `.example`.

## الربط

```
نص الإعلان / صورة / رابط
  → POST /extract                     (schema 1.1، القواعد أو GPT)
  → integration/matcher_adapter.py    (to_matcher_input)
  → team_data/matcher.py check()      (+ entities.json + reports.json)
  → الجهة، ونتيجة كل قناة، والحكم
```

- التشغيل: `scripts/run_team_cases.py --extractor rules|gpt --input text|image`.
- المخطط: `integration/matcher_input.schema.json`.
- النتائج: `reports/team_cases/`.

## ما تحتاجه من صاحب القاعدة (عارف)

- **`account_holder` المسجّل لكل آيبان موجود** في `entities` لكن المطابِق لا يستخدمه. مقارنة صاحب الحساب المستخرج باسم الجهة تكشف حالة «آيبان صحيح الصيغة باسم شخص».
- **حقل `channel_status` أو `valid_from`/`valid_to` لكل قناة.** حالة T11 (حساب جديد يدّعيه مورد) تُحسم حاليًا لأن الآيبان غير مسجّل فقط. مع التاريخ نفرّق بين «حساب قديم أُلغي» و«حساب لم يُسجَّل أبدًا».
- **`whatsapp` منفصل عن `mobiles`** إذا كان للمكتب واتساب برقم مختلف، و**نطاقات البريد** إن أردنا مطابقة البريد.
- لا شيء منها يمنع الدمج الآن، فالحالات العشرون تنجح بدونها.
